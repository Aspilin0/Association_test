# 05 — 候选词生成 与 back 机制

## 1. 候选词生成 pipeline（全局结构感知）

候选生成不是只看「当前词 + 种子 + 历史」，而是读取**在线网络状态**，在全局结构下生成。

```
在线网络状态(network_state) + 当前词 + 种子 + 历史链
   → LLM(高温度) 生成 ≥12 个候选
   → embedding 去重 + 过滤高频词 + 全局结构重排(多样性/融入度/覆盖)
   → back 排序惩罚
   → 取前 candidate_count(6~8) 返回
```

**覆盖目标**（LLM 生成与重排共同参考）：
1. **维持当前簇**——延续当前主题/情绪；
2. **桥接其他簇**——连接已浮现的其他主题；
3. **自由跳跃**——跳出既有结构，探索新方向。

### 在线网络状态（生成上下文）

候选生成与评分（02）共享同一份、随联想实时更新的 `network_state`（定义见 01）：

```json
{
  "node_count": 12,
  "centroid_words": ["家", "房子"],
  "dominant_emotion": "sadness",
  "emotion_distribution": { "sadness": 4, "joy": 2 },
  "top_central_words": ["房子", "家"]
}
```

### Prompt 模板（示意）

```
你是词语联想助手。给定种子词、当前词、联想链历史，以及当前网络结构摘要，
生成 12 个联想候选词。
要求：多样性高；兼顾「维持当前簇 / 桥接其他簇 / 自由跳跃」三种倾向；
避免与历史词重复；每个候选用中文 1~6 字。
只输出 JSON 数组：["词1", "词2", ...]

种子词：家
当前词：房子
历史链：家 → 房子
网络结构：核心词=[房子,家]；主导情绪=sadness；已现词=12个
```

## 2. 去重与过滤

- **去重**：候选两两之间、候选与历史词之间，用 embedding 余弦相似度去重（阈值默认 0.85）。
- **高频过滤**：出现次数 `occurrences ≥ 2` 的历史词默认不再作为候选（除非用户明确翻页/刷新）。

## 3. back 机制

定义：历史已出现过的词再次出现（无论被选择还是自由输入）。

- **候选排序惩罚**：历史词仍可出现在候选池，但排序得分 ×`0.5`（默认惩罚系数，可配）。
- **命中即强信号**：一旦用户真的再次选择/输入历史词：
  - 后端标记 `is_back=true`，`occurrences += 1`；
  - 评分中 `reaction_time` +0.1 加成，`connectivity` 因 occurrences 上升（见 02）；
  - 强化该词与其历史出现处的 `association` 边权重。

> 排序惩罚与评分加成不矛盾：排序上"不易被推荐"，但用户主动选择时"更值得标记"，符合荣格"重复=干扰征象"的理论。

## 4. 自由输入

- 前端在候选池旁提供输入框 + 回车提交，`source="free"`。
- 自由输入的词**不受候选排序惩罚影响**，但仍参与去重、back 判定与评分。
- 反应时同样从「渲染候选」到「回车提交」计时。
